# 视频动态壁纸说明

本文记录当前版本的视频壁纸行为、使用方法和验收边界。内容限定于仓库中已实现的 macOS 原生路径；构建或单元测试通过不等于 GUI 播放已验收。

> 2026 年 9 月 24 日修复记录：旧构建曾因 SwiftUI `WindowGroup` 场景恢复状态导致进程仍在运行但窗口数为 0，看起来像“打不开”。当前 macOS 原生入口改为由 `AppDelegate` 显式创建并持有主窗口：启动时强制显示、关闭时只隐藏、从菜单栏或 Dock 重新打开；即使壁纸恢复较慢或核心返回错误，管理窗口也先可用。

## 当前实现

- 支持媒体库中的本地 `MP4`、`MOV` 文件。可以将文件拖入应用窗口，或使用原生文件选择器导入；导入会复制到媒体库。
- Rust 核心通过 AVFoundation 创建视频播放会话，以桌面层级窗口显示在桌面图标之下，不抢前台焦点，并跟随系统空间。
- 使用 `AVQueuePlayer` 和 `AVPlayerLooper` 循环播放；视频支持静音，默认偏好可在设置中更改。
- 应用视频时先准备候补会话。只有播放器就绪、首帧可用后才替换旧视频或静态壁纸；解码/首帧失败或等待超过 15 秒时，候补会话被丢弃并报告错误，原壁纸应保持不变。
- 每台显示器单独保存壁纸分配和播放状态。状态通过原生 bridge 推送到界面。
- 停止视频会销毁该屏视频会话、清除自动恢复分配，并将首帧海报保留为系统静态壁纸。
- 应用启动、显示器重连及休眠唤醒时会尝试恢复已保存的播放分配。退出应用会同步清理播放会话；关闭管理窗口只隐藏窗口，应用继续运行。
- 切换到静态图片时，系统确认设置成功后才销毁该屏旧视频会话。
- 视频会话创建与停止路径不再使用会导致进程中止的 `expect`：AVFoundation 的可选填充常量改为可报告错误，停止不存在的会话改为返回明确错误；设置、缩略图缓存及回调注册的 Mutex 发生 poisoned 时也会恢复内部状态；这只保证错误可控，不替代真实桌面播放验收。
- macOS 27 上前端构建改为由脚本显式结束的 Vite API 调用，避免 Tailwind 文件系统 worker 残留导致 Xcode 构建看似卡住。

## 使用流程

1. 首次运行选择媒体库目录；之后可在设置面板更改。
2. 将 MP4/MOV 拖入应用窗口，或通过文件选择器导入。
3. 在媒体网格中选择视频及目标显示器，再执行应用操作。
4. 在该屏播放控制区暂停、恢复或停止。菜单栏可批量控制全部显示器。
5. 关闭管理窗口不会停止动态壁纸；从菜单栏退出应用才会清理播放会话。

## 切换与恢复语义

- 快速连续选择不同视频时，generation 令牌使旧的准备请求失效，避免过期会话覆盖最新选择。
- 准备中可以停止；停止会令对应 watcher 失效。
- 正在播放或作为当前桌面海报来源的文件受到删除保护。
- 无 EDID 序列号的显示器会使用临时 ID；拔插后可能需要重新分配壁纸。
- 显示器拔除、空间切换及设备驱动差异可能影响画面表现，应在目标系统与显示器组合上验证。

## 当前不支持或不保证

- GIF、动态 HEIC、网络串流、播放列表、定时轮播、按 Space 独立壁纸和锁屏/登录界面壁纸。
- 静态图片上的水滴玻璃、雪花、樱花等实时叠加效果尚未实现；当前动态壁纸指视频文件壁纸。
- 不能仅凭 Rust 测试或 Xcode 构建判定视频在桌面正确播放。需在真实 GUI 会话观察画面、循环、静音、切换回滚、播放控制及退出清理。

## 建议验收清单

- [ ] 首次启动引导可选择目录、取消或稍后设置；重启后引导状态正确。
- [ ] 导入 MP4/MOV 后出现媒体项，预览与缩略图正常。
- [ ] 在每台在线显示器应用视频，确认进入播放态，桌面图标及交互不被遮挡。
- [ ] 检查循环播放无明显黑帧/停顿，静音偏好符合预期。
- [ ] 播放中切换至另一视频及静态图片；新内容成功后替换，准备失败时原画面保留。
- [ ] 快速连续切换、准备中停止、暂停/恢复/停止均不产生残留窗口或过期播放。
- [ ] 关闭管理窗口后播放继续；菜单栏批量控制与退出清理符合预期。
- [ ] 验证显示器拔插、休眠唤醒和应用重启恢复；记录临时显示器 ID 的表现。
- [ ] 执行长时间播放及 Mission Control/多 Space 检查，并记录 macOS 版本、机器、视频编码/分辨率、显示器布局和结果。
